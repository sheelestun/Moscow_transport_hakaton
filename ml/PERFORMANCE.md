# ML-модуль: производительность и надёжность

Все цифры — замеры 26.09.2026 на ноутбуке (Windows 10, Docker Desktop, 12 CPU), CatBoost-ансамбль из 5 моделей
+ модели интервала и вероятностей, 56 признаков. Воспроизвести — команды в конце.

## Точность (MAE, секунды; меньше — лучше)

| Схема проверки | Модель | Бейзлайн `cur_dev_s` | Что показывает |
|---|---|---|---|
| holdout: train → test | **39.8** | 93.4 | прокси скора платформы (оценка score ≈ 1.0) |
| proxy «как validate» (5 фолдов блоками по 30 мин) | **38.8** | 88.4 | так устроен validate: соседние моменты T тех же ТС |
| LOVO: ТС отложено целиком вместе с клонами | **78.9** | 88.4 | честное качество на новом ТС / другом дне |

Неопределённость (holdout): факт попадает в `delay_interval_sec` в **80%** случаев (цель 80%, конформная
калибровка); вероятность опоздания `p_late`: AUC **0.97**, откалибрована (прогноз ~0.89 → реально 0.95).

## Скорость (latency)

Прогон всех 151 точки validate через HTTP (`replay_validate.py`), телеметрия ТС за 90 минут до T в каждом запросе:

| Где | `/predict`, одна точка | `/predict/batch`, 151 точка |
|---|---|---|
| Docker-контейнер (`docker compose up ml`) | p50 **44 мс**, p95 55 мс (с HTTP); внутри сервиса p50 19 мс | 3.0 с всего, **20 мс на точку** |
| Локально (uvicorn) | p50 54 мс, p95 65 мс (с HTTP); внутри p50 24 мс | 1.6 с всего, 10.5 мс на точку |

Ориентир ТЗ — < 1–2 с на поток ТС: запас более чем в 20 раз. Очередей нет: поток из сотен ТС раз в 30 с
обрабатывается одной пачкой за секунды.

Из чего складывается время: признаки ~10 мс (план ТС разобран один раз при старте, телеметрия векторно),
5 моделей ~3 мс, причины (приближённый SHAP) ~35 мс на точку при одиночном запросе.

## Онлайн = батч

Онлайн-прогноз сервиса совпадает с `submission.csv` на **151/151** точке, максимальная разница **0.00 с**:
признаки считает одна и та же функция `features/tabular.point_features`. `/predict` и `/predict/batch` дают
одинаковый ответ.

## Деградация (сервис не падает)

Проверено запросами к контейнеру:

| Ситуация | Ответ |
|---|---|
| Обрыв связи: телеметрии нет | 200, `data_status: no_telemetry`, прогноз по подсказке и плану, `confidence` ×0.5 |
| Все координаты невалидны / нет свежих координат > 3 мин | 200, `no_telemetry` / `stale`, `confidence` снижена |
| В буфер попали пакеты позже T | игнорируются, прогноз не меняется (анти-утечка на стороне сервиса) |
| Ошибка модели или признаков | 200, `data_status: fallback`, прогноз = `cur_dev_s` (бейзлайн) вместо HTTP 500 |
| Одна плохая точка в пачке | пачка пересчитывается поштучно, остальные точки не страдают |
| Нет планового расписания ТС | 422 с понятным текстом (прогнозировать не к чему) |
| Переобучили модель | `POST /reload` подхватывает новые файлы без перезапуска контейнера |

## Как воспроизвести

```bash
python ml/src/train_catboost.py --dataset ./dataset --eval          # точность по трём схемам
python ml/src/train_catboost.py --dataset ./dataset --fit           # финальные модели + submission.csv
docker compose up -d --build ml                                     # контейнер ML на :8001
python ml/src/replay_validate.py --dataset ./dataset --submission submission.csv \
    --url http://localhost:8001 --send-schedule                     # онлайн = батч, latency
curl http://localhost:8001/metrics/model                            # живые метрики сервиса
```
